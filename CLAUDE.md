# Проект: тренажёр литовского (lt)

Полный контекст замысла и решений — `DECISIONS.md` (локальный, вне репозитория — в `.gitignore`).

## Публичный репозиторий — что НЕ коммитить
Репо **публичное** (GitHub Pages, `https://ku6opr.github.io/lt/`). Перед каждым коммитом:
- НЕ коммитить секреты: токены, API-ключи, пароли, `.pem/.key/.p12`, `.env`. Секретов в проекте быть не должно (статика, без бэкенда).
- НЕ коммитить приватные данные: рабочие/личные email, IP, телефоны, внутренние ссылки.
- НЕ коммитить `node_modules/`, `dist/`, логи — они в `.gitignore`; не убирать их оттуда.
- Коммитить под **GitHub noreply**-почтой (`Ku6opr@users.noreply.github.com`), не под рабочей — иначе email утечёт в публичную историю. В репо настроено (`git config user.email`); не переопределять на рабочую.
- Данные тренажёра (слова, формы, переводы) — открытые, коммитить можно.
- Проверка перед публикацией новых файлов: `git grep -nEI '(secret|password|api[_-]?key|token|BEGIN (RSA|OPENSSH|PRIVATE))'` + глянуть `git ls-files`.

## Принципы (следовать во всех новых темах/уроках)
Подробно в `DECISIONS.md` → «Принципы проектирования». Кратко:
- Данные, а не код: уровни/слова/падежи/предлоги/кривая сложности — в `data/`+`topics/`, UI считает из данных.
- Лексика отдельно от тренажёра (переиспользуемые паки слов).
- Правильность важнее удобства: грамматику не подделывать.
- Самопроверка без наказаний (нет автопроверки/баллов/штрафов).
- Две ортогональные ручки: галочки = содержание, слайдер = подача.
- Сложность = количество/качество подсказок.
- Проверять результат перед «готово» (сборка + прогон, консоль чистая).

## Разработка
- Стек: Svelte + Vite + PWA. `npm run dev` (локально), `npm run build` (сборка в `dist/`).
- Деплой: push в `main` → GitHub Actions (`.github/workflows/deploy.yml`) собирает и публикует на Pages.
- Пуш — через SourceTree (в песочнице нет доступа к keychain).

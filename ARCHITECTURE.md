# Архітектура і принципи розробки (для агентів)

Читай це ПЕРЕД будь-якою розробкою в проєкті. Тренажер литовської, Svelte+Vite+PWA, статика на GitHub Pages. Продуктові рішення — `DECISIONS.md` (локальний), правила репозиторію — `CLAUDE.md`.

## Головні принципи (не порушувати)

1. **Правильність важніша за зручність.** Литовські форми НІКОЛИ не вигадувати. Тільки з Wiktionary (див. пайплайн). Українські форми/переклади пишу вручну (native-level). Сумнівне — позначати, не гадати.
2. **Дані, а не код.** Рівні, слова, відмінки, прийменники, дієслова, фрази, теми — це дані у `src/lib/data/`. UI/рушій рахують з даних (кількість рівнів = `LEVELS.length`/`PHRASE_TIERS.length`, і т.п.). Новий контент = новий запис у даних, без правки рушія.
3. **Самоперевірка без покарань.** Вводиш → розкриваєш → порівнюєш сам. Без балів/штрафів/лічильників. Нескінченний урок.
4. **Складність = кількість і якість підказок.** Монотонно від легкого до складного, без «мертвих» однакових сходинок.
5. **Перевіряй результат перед «готово».** Кожна зміна: `npm run build` + прогін (node-скрипт на логіку + браузер через Playwright, консоль чиста). «Код виконався» ≠ «користувач бачить правильно».
6. **Мова.** UI і глоси — українські. Технічні терміни/код — як є.
7. **Живі куровані фрази — ОДРАЗУ, не відкладати.** Кожен урок з самого початку має куровані теми-фрази (осмислені, різноманітні, вивірені пари), як у іменників. Випадкове парування навіть з категоріями дає штучні/дивні сполучення — це неприйнятно. Теми = частина уроку, а не «пізніше».
8. **Без хибного узгодження в глосі.** Укр. рід ≠ литовського (і укр. має середній рід). НЕ склеювати укр. прикметник+іменник у фразу, якщо не зберігаємо укр. рід. Показувати значення слів окремо (значення слова під завданням, значення другого + питання в підказці).

## Пайплайн даних (як додавати слова)

```
Wiktionary → data-source/*.json → scripts/build-words.mjs → src/lib/data/words.js
```
- **Фетч форм:** запускати сабагентів (`general-purpose`, паралельно, по ~12-16 лем). Кожен: MediaWiki `action=parse` rendered HTML en.wiktionary.org, парсити `inflection-table` напряму (НЕ через summarizer — він псує діакритику), fallback lt.wiktionary. Стрип лише наголосів (U+0300/0301/0303 + dotted-i артефакт), зберігати `ą č ę ė į š ų ū ž`. 6 відмінків × sg/pl, порядок nom,gen,dat,acc,ins,loc. Не знайдено → `found:false`, не вигадувати. Писати JSON у `data-source/`.
- **Метадані вручну** в `build-words.mjs`: `META[lemma] = {t: тип, uk: переклад, f:[gen,dat,acc,ins,loc]}` (nom = uk), `CAT[lemma]` (категорії), `THEME_MEMBERS` (членство в темах). Потім `node scripts/build-words.mjs`.
- **Джерело лексики під курс користувача:** `LT words 1.pdf`, `LT words 2.pdf` (Modulis pirmas / Žodynas A2) — авторитетний список з точними укр. перекладами і `(ką?)`-керуванням дієслів. Нову лексику брати звідси в першу чергу.
- `pl:[]` = singularia tantum (дозволено); рушій у «Всі слова» не бере таке слово, коли випала множина.

## Схема слова (`words.js`)
`{ id, type (тип відмінювання), cat:[категорії], themes:[id тем], uk, ukForms:{nom,gen,dat,acc,ins,loc}, sg:[6], pl:[6|0] }`
- Типи відмінювання (іменники): `as,is_b,is_m,ys,us,ius,uo_m,a,ia,e,is_f,uo_f` — 12, у `declensions.js` (парадигми-зразки для таблиці-шпаргалки).

## Рушій задач (`engine/generate.js`)
- `newTask(state, prev)` — `prev={wordId,caseId}` для м'якого пріоритету НЕ повторювати слово/відмінок.
- Два режими за темою:
  - **«Всі слова» (`theme==='all'`) — граматичний рушій:** пул = слова за галочками типів/падежів/числа. Ціль-відмінок з обраних. Складність (`LEVELS`, 10 рівнів) керує подачею: режим промпту (`lt-nom → lt-tonom → lt-othercase → uk → mix-all`), питання, прийменники, дієслова. **Драйвери** (прийменник АБО дієслово) керують відмінком і сигналять його; сумісність зі словом за `cat` (щоб не було нісенітниць). Драйвер: `{case, ukCase, accepts}` — `ukCase` окремо, бо укр. керування ≠ литовського.
  - **Тема (курований банк фраз) — `phraseTask`:** фрази з `phrases.js`. `PHRASE_TIERS` (6 рівнів) керує подачею. Відмінок фіксований фразою.
- Основа показу = найбільший спільний префікс форм; хвіст червоний.

## Фрази (`phrases.js`)
- Генератори `gen/head/ant` → фраза `{lead (лит.), w (слово), c (відмінок), ukPre, ukForm, uk}`. **Укр. глос складається автоматично з вивірених `ukForms`** → правильність гарантована; вручну курую лише які слова під який патерн (осмислені, живі пари: «булка з сиром», «їхати потягом», «дзвонити судді»).
- Тег-рандом за категоріями недостатній для природності — тому явні куровані пари (принцип «повний список комбінацій»).

## Складність (монотонність — критично)
- «Всі слова»: 10 рівнів, кожен реально складніший.
- Тема: 6 рівнів `PHRASE_TIERS`: `lt+fullq → lt+q → lt+none → uk+q → uk+none → mix+none`. Підказка тільки спадає. Останній — обидва напрямки.
- Слайдер сам міняє довжину під режим; рівень затискається при зміні теми.
- На розкритті — переклад фрази під відповіддю, якщо зверху його не було.

## UI (`components/`)
`TopicsScreen` (список тем-уроків) · `Trainer` (екран уроку) · `TaskCard` (завдання+ввід+розкриття) · `CheatTable`/`CheatStack` (таблиця-шпаргалка десктоп/мобільний) · `StudySelector` (складність+галочки+теми) · `WordForm` (основа+червоний хвіст).

## Уроки (topics)
- **vidminky** (іменники): рушій `generate.js`, компоненти `CheatTable/CheatStack/StudySelector`, теми-фрази.
- **adj-nom / adj-cases** (прикметники — ДВА уроки): рушій `engine/adjectives.js` — завдання ЗАВЖДИ узгодження «прикметник + іменник» (іменник з паку уроку 1, рід/число/відмінок від нього; прикметник інфлектуєш). Компоненти `AdjCheatTable/AdjCheatStack/AdjSelector`. Осі: відмінки, тип I/II/III, рід (3-toggle ч./ж./обидва), число. Складність = `PHRASE_TIERS` (6, монотонно). Дані `adjectives.js` (`build-adjectives.mjs`, форми Wiktionary — 24 на слово: рід×число×відмінок). Укр. глос = пара через « · » (без хибного узгодження, бо укр. рід ≠ литовського).
  - **Розбиття на два уроки — параметр `scopeCases` в topic (`topics/adjectives.js`).** `adj-nom`: `scopeCases:['V']`, обидва числа — вчимо лише називний (узгодження роду/числа), шпаргалка `cheatCases:['V']` (лише називний), у селекторі блок «Відмінки» прихований (`showCases` при >1 падежі). `adj-cases`: `scopeCases` = непрямі (K/N/G/In/Vt), називний НЕ ціль, але у шпаргалці є (`cheatCases` = всі 6) для довідки; слово дано в називному (промпт — цитатна форма). Trainer інжектить `caseScope` у стан рушія (`stateOf`); рушій бере відмінок лише зі scope (і в темах теж). Налаштування per-topic: `lt-trainer-adj-nom-v1`, `lt-trainer-adj-cases-v1`.
- Реєстр `topics/index.js`; `App` тримає `topicId`; `Trainer` параметризований темою; налаштування per-topic (`settingsFor(topicId)`).
- **Прикметники, пари:** ВСІ завдання (і «Всі слова», і теми) беруться з курованого банку `adjPhrases.js` (96 пар) — випадкове парування давало нісенітниці («дерев'яне море»), тому лише куровані логічні пари. «Всі слова» = union усіх пар, фільтр за типом/родом; тема → пари теми. Відмінок випадковий; лише ОДНИНА (укр. форм множини не зберігаємо).
- **Глос прикметника — укр. фраза СКЛОНЕНА у відмінок цілі.** `ukAdjPhrase` (engine): іменник бере готову форму з `word.ukForms[відмінок]` (прийменник у місцевому — «у дитині» — рушій виносить перед прикметник); прикметник склоняє `ukAdjForm` (укр. відмінювання регулярне: тверда `-ий` / м'яка `-ій` група × рід m/f/n × відмінок; знахідний ч.р. = родовий для істот, детект `ukForms.acc===ukForms.gen`). Приклад: `малий+дитина` родовий → «малої дитини», місцевий → «у малій дитині». Питання = литовський цільовий рід (може не збігатися з укр. — норм).
- **Множина непрямих відмінків — укр. форм іменників НЕМА** (`ukForms` лише однина; є `ukPl` — називний мн.). Тому pl+непрямий НЕ склеюється: показуємо «прикм. · імен.» у називному мн. (через « · », сигнал що це значення); відмінок сигналить питання. Називний мн. (V) — коректний. Розширення = додати укр. відмінкові форми мн. іменників (обережно: родовий мн. нерегулярний).
- **`boundedPrefix`** (не `commonPrefix`) для основи прикметника: коли називна форма є префіксом непрямих (brangi ⊂ brangios), звичайний префікс з'їдає весь хвіст → нема що вводити. Обмежуємо, щоб у найкоротшої форми лишався ≥1 символ.
- **Множина** працює: кожен іменник має `ukPl` (укр. називний множини — правило + `UK_PL` винятки для нерегулярних/біглих голосних у `build-words.mjs`), прикметник `ukPl` (білі/великі). У множині глос показує укр. називний множини (значення), відмінок сигналить питання. Те саме в уроці 1 (для мн. глос використовує `type.ukPl`).
- **Відкладено:** вищий/найвищий ступінь, означені форми.

## Мова інтерфейсу і глосів (uk / ru / en)
Вихідна мова навчання (не литовська ціль) перемикається на головній (UA/RU/EN, `stores/lang.js`, persist `lt-lang-v1`, дефолт uk). Три шари:
- **UI-словник** `i18n/ui.js` (`UI[lang][key]`): весь chrome, назви відмінків (`caseNames`), теми (`themes`), роди, підписи. Компонент: `$: L = UI[$lang]`. Теми в `topics/*.js` — `title/subtitle/trainerTitle` як `{uk,ru,en}`.
- **Дані слів**: `words.js` має `ru/ruG/ruPl/ruForms/en/enPl` (крім `uk*`), `adjectives.js` — `ru{M/F/N}/en`. Джерело: `data-source/ru-en-nouns.json` + `ru-en-adj.json` (згенеровано сабагентами, підмішується в `build-words.mjs`/`build-adjectives.mjs`). Англ. — без відмінків (лише база + множина).
- **Рушій глосів** language-parametrized через `state.lang` (Trainer інжектить `$lang` у `stateOf`). Прикметники (`engine/adjectives.js`): `adjPhrase(lang,...)` + алгоритми `ukAdjForm`/`ruAdjForm` (рос.: тверда/м'яка/задньоязикова/`-ой` група; знахідний = родовий для істот) + `ADJ_Q` з uk/ru питаннями; en — база + прийменник (`EN_PREP`). Іменники (`engine/generate.js`): `nounForm`/`caseQ` per lang. Питання відмінків — `cases.js` (`qUk/qRu/qEn`).
- **Драйвери (прийм./дієсл.) — усі 3 мови.** `prepositions.js`/`verbs.js` мають `ru/ruCase/en` (+`uk/ukCase`). `ruCase` — рос. відмінок, яким керує рос. прийм./дієсл. (може ≠ литовському: `už`→за+орудний, `pas`→к+давальний, `apie`→про+знахідний). ВАЖЛИВО: рос. `ruCase` НЕ використовує предложний (`Vt/loc`), бо `ruForms.loc` містить вшитий прийменник → подвоєння; тому `apie`→`про`(acc), не `о`(prep). En драйвер: форма-база (без відмінка).
- **Множина непрямих відмінків** — Є (`data-source/ru-uk-plural.json` → `word.ruPlForms/ukPlForms` = {gen,dat,acc,ins,loc-з-прийменником}, підмішує `build-words.mjs`). `nounForm` (обидва рушії) для pl бере відмінкову форму, не називний. Прикметник pl склоняється алгоритмом. En іменник — база + прийменник (без відмінків, без артиклів). Ru прикметник: питання за литовським родом (дрібний неточний хінт).
- **Верифікація даних**: ru/en згенеровано сабагентами + НЕЗАЛЕЖНИЙ ревіз-прохід (4 агенти по nouns + 1 adj, звірка з ru.wiktionary). З 287+33: виправлено 2 (loc днів тижня — предложний замість темпорального знахідного). Решта чисто. Правки мерджаться у `data-source/ru-en-*.json`.

## Прогрес і адаптивність (`stores/progress.js`)
Тихий трекінг + підтягування слабких. **Зсув від принципу «без автоперевірки»** — свідомо заданий користувачем; тримаємо НЕпунітивним: сигнал прихований, годує лише вибірку, без балів/червоного; максимум — ненав'язлива зелена ✓ при збігу.
- **Сигнал**: на розкритті `fold(stemPrefix+ввід) === fold(targetForm)`. `fold` згортає литовську діакритику (ą→a, į→i, ū→u, ž→z, …) + lower/trim — спецлітери вводити НЕ обов'язково. Порожній ввід → `null` (лише експозиція, не промах).
- **Виміри (ключове)**: одна задача пише КІЛЬКА ключів одним результатом (`record(topic, keysFor(t), correct)`): `form` (слово×відм×число), **`cell` = парадигмова клітинка (тип×відмінок×число) = ЗАКІНЧЕННЯ**, і осі `case|`, `ntype|`/`atype|`, `num|`, `gender|`. Тому 5 правильних `-as` родовому знижують усе закінчення `-as|K` — включно з невиданими словами того типу (не лише ті 5 слів).
- **Вибір задачі — стратифікація за типом** (`Trainer.makeNewTask`): кожен з 8 кандидатів генерується з обраного типу (`genTask({...state, types:{[ty]:true}})`), тип обирається зважено за «слабкістю» типу (`dimWeight(ntype|X)`, невидане=1). Так УСІ закінчення беруть участь нарівні, а не пропорційно кількості слів типу (інакше `-as` зі 104 словами душив би `-ius` з 1 словом). Фінальний вибір серед кандидатів = `0.6·w(cell) + 0.4·w(form)` (клітинка-закінчення домінує, слово — довесок для вокабуляра). `w`: невидане ≈1.0, промахи ↑, освоєне ↓, з часом ↑ (resurface). М'яко (зважений random, не argmax). Свіжий прогрес → рівномірно по типах.
- **Стан**: `localStorage` `lt-progress-v1`, per-topic `{forms:{key:{s,o,m,t}}, tick}`. `keyStat()` — для майбутнього дашборду (виміри вже пишуться).
- **Дашборд** (`StatsPanel.svelte`, per-topic, тумблер «Статистика» в уроці): теплокарта тип×відмінок (клітинки = майстерність закінчення, колір red→green за точністю, сірий=невидане, блакитний=показане-без-вводу), тумблер sg/pl, слабкі слова (чіпи, accuracy), тотали (відповідей/точність/покриття), кнопка «Скинути» (для тесту, чистить прогрес теми). Читає стор `progress` напряму.

## Збереження
`localStorage`, ключ `lt-trainer-<topic>-v1`, per-topic: слайдер, галочки, тема, видимість шпаргалки. Без статистики.

## Як додати новий урок/тему
1. Дані слів через пайплайн (фетч+META).
2. Якщо структура інша (напр. прикметники мають рід) — окремий пак даних + за потреби окрема таблиця-шпаргалка і гілка рушія; максимально переюзати компоненти.
3. Реєстр: `src/topics/index.js` + `src/topics/<topic>.js` (title/kicker/glyph).
4. Складність — дані (масив рівнів), монотонна.
5. Перевірити: build + node + браузер (обидва лейаути, консоль чиста).

## Верифікація перед «готово»
- `npm run build` без помилок.
- node-скрипт: логіка (пул не порожній, форми/відмінки валідні, 0 null/undefined, монотонність рівнів).
- Playwright: рендер desktop+mobile, розкриття, консоль 0 errors.
- Тимчасові файли прибрати (`.playwright-mcp`, скриншоти, scratch).
